# image-uploads Specification

## Purpose
Lets signed-in users attach an image to an activity, stores it safely in the AEP's own Azure storage, and serves it back through the app.

## Requirements

### Requirement: Upload requires a signed-in user

The system SHALL accept an image upload only from a signed-in user. A guest SHALL receive an authentication error and nothing SHALL be stored.

#### Scenario: Guest uploads

- **WHEN** a guest sends an image to the upload endpoint
- **THEN** the answer is 401 with a Portuguese message and nothing is stored

#### Scenario: Signed-in user uploads

- **WHEN** a signed-in user sends a valid image
- **THEN** the answer is 201 with the address of the stored image

### Requirement: Only real images within the size limit

The system SHALL accept only JPEG, PNG and WebP images, decided from the file content (not from its name or the declared type), of at most 5 MB, one file per request. Anything else SHALL be rejected with a Portuguese validation message and nothing SHALL be stored.

#### Scenario: Wrong type

- **WHEN** a user uploads a PDF renamed to `foto.png`
- **THEN** the answer is 400 and nothing is stored

#### Scenario: Too large

- **WHEN** a user uploads a 6 MB image
- **THEN** the answer is 413 or 400 with a Portuguese message and nothing is stored

#### Scenario: Several files

- **WHEN** a request carries two files
- **THEN** it is rejected

### Requirement: Safe storage

The system SHALL store each image under a random name generated by the server, with an extension and content type chosen from the detected type, and SHALL NOT use the uploaded file name or any user-supplied path. The storage account SHALL NOT allow public access and SHALL require TLS 1.2 or higher.

#### Scenario: Hostile file name

- **WHEN** a user uploads `../../x.png`
- **THEN** the stored name is a server-generated random name

### Requirement: Images are served by the app

The system SHALL serve stored images at `/media/activity-images/<name>` over the app's own host, with the stored content type, long-lived caching headers and `X-Content-Type-Options: nosniff`. Names that do not match the generated pattern SHALL answer 404. Reading an image SHALL NOT require sign-in.

#### Scenario: Reading an image

- **WHEN** a guest requests an uploaded image
- **THEN** the image is returned with its content type and cache headers

#### Scenario: Unknown or malformed name

- **WHEN** a request names an image that does not exist, or a path with `..` or slashes
- **THEN** the answer is 404

### Requirement: Activities keep working images

An activity SHALL store the returned address as its image. Activities whose image is a shipped illustration under `/activity-illustrations/` SHALL keep working unchanged. The activity editor SHALL show an upload control, a preview, and a Portuguese error when the upload fails.

#### Scenario: Editing an activity

- **WHEN** an admin uploads an image in the editor and saves
- **THEN** the activity card and detail page show that image

#### Scenario: Upload failure

- **WHEN** the upload fails
- **THEN** the editor shows a Portuguese error and keeps the previous image

### Requirement: No credentials in production

In Azure the app SHALL reach storage with its managed identity and SHALL NOT use an account key, a connection string or a shared access signature. Local development SHALL use the Azurite emulator with its well-known development account. The upload route SHALL be answered 404 or 503, never succeed, when no storage is configured.

#### Scenario: Production configuration

- **WHEN** the app settings of the Production Web App are inspected
- **THEN** they contain no storage key or connection string

#### Scenario: Missing storage

- **WHEN** no storage is configured and a user uploads an image
- **THEN** the answer is an error with a Portuguese message and nothing is stored

### Requirement: Third-party upload service removed

The system SHALL NOT depend on UploadThing: its package, route, environment variables and allowed image domain SHALL be removed, and documentation SHALL describe the Azure storage instead.

#### Scenario: Dependency check

- **WHEN** the repository is searched for UploadThing
- **THEN** no code, configuration or setting refers to it
